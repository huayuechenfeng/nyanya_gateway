# 零基础教程：用 J2ME / Symbian 老手机收发 QQ 消息

这是一份真正从零开始的 Windows 教程。假设你手里只有：

- 一台 Windows 10/11 电脑；
- 一部可以连接 Wi-Fi 的 J2ME 或 Symbian 手机；
- 自己合法持有的 J2ME MobileQQ JAR，或者已经安装好的 Symbian QQ2013；
- 一个可以正常登录的 QQ 账号。

> **开始前请先确认你能接受账号风险：** NapCat 属于第三方 QQ 协议/自动化接入工具，可能触发 QQ 风控，出现强制下线、限制登录、账号冻结等情况。不要使用主力 QQ 账号、保存重要聊天资料的账号或难以找回的账号，建议专门准备一个测试账号。因平台风控、封禁或账号处置造成的账号及数据损失，由使用者自行承担，本项目及贡献者不承担责任。

> **本教程描述的是「局域网形态」**：手机、网关和 NapCat 都在家里同一个局域网。如果你希望手机在外网也能用（网关放公网服务器、NapCat 留家里），请看 `nyanya-gateway-class/异地部署.md`——那条路线不推荐新手，且必须自行补公网防护。



## 0. 先理解你正在搭什么

老版J2ME / Symbian 手机QQ已经不能直接连接今天的 QQ 服务。Nyanya Gateway Class 的做法，是让电脑替老手机完成现代 QQ 连接，再把结果翻译成老客户端认识的格式。

```text
J2ME / Symbian 手机
        │
        │  家庭 Wi-Fi / 局域网
        ▼
Nyanya Gateway Class（电脑）
        │
        │  OneBot v11 WebSocket
        ▼
NapCat + QQ（同一台电脑）
```

这里有三个容易混淆的“密码”：

| 名称 | 在哪里使用 | 是什么 |
| --- | --- | --- |
| QQ 登录凭据（实际的QQ密码） | NapCat 登录 QQ 时 | 由 NapCat/QQ 管理，本项目不读取 |
| NapCat token | NapCat 和网关之间 | 你在 NapCat WebSocket 服务中设置的访问密钥 |
| `deviceToken` | 老手机 QQ 的密码栏 | 你自己设置的局域网登录密码，不是真实 QQ 密码 |

后面在老手机登录页看到“密码”二字时，一律填写 `deviceToken`，不要填写真实 QQ 密码。

## 1. 准备文件和网络

### 1.1 下载 Gateway Class 发布包

下载名称类似下面的 ZIP：

```text
Nyanya-Gateway-Class-v0.1.0.zip
```

右键 ZIP，选择“全部解压”。建议解压到一个容易找到、路径不要太深的位置，例如：

```text
D:\Nyanya-Gateway-Class-v0.1.0\
```

不要直接在压缩包预览窗口里双击脚本。脚本需要创建配置、日志和补丁 JAR，必须先完整解压。

解压后，顶层应该至少能看到：

```text
README.md
package.json
docs\
nyanya-gateway-class\
packages\
```

如果你使用的是 GitHub 源码，目录会更多，这是正常的。后面的操作仍在 `nyanya-gateway-class` 目录中进行。

### 1.2 确认电脑和手机在同一个局域网

最简单的情况是：电脑和手机都连接同一个家庭路由器。电脑可以使用网线，手机使用 Wi-Fi，只要它们属于同一个家庭局域网即可。

以下网络经常会阻止设备互相访问：

- 酒店、商场、学校等带“客户端隔离”的公共 Wi-Fi；
- 手机热点开启了设备隔离；
- 电脑同时连接了多个 VPN、虚拟网卡或模拟器网络；
- 路由器的访客 Wi-Fi。

第一次测试尽量使用普通家庭 Wi-Fi，并暂时关闭不需要的 VPN。

**本节成功标志：** 发布包已经完整解压，电脑和手机都已接入同一个可信局域网。

## 2. 安装并检查 Node.js

网关和 JAR 注入器需要 Node.js 22.5 或更高版本（Class 网关使用了 Node.js 22.5 引入的 SQLite 模块）。推荐从 [Node.js 官方网站](https://nodejs.org/) 安装当前 LTS 版本，安装过程保持默认选项即可。

安装完成后：

1. 按 `Win + R`；
2. 输入 `powershell`，按 Enter；
3. 在蓝色或黑色窗口中输入：

```powershell
node --version
```

如果输出 `v22.5.0` 以上的 22.x 版本、`v24.x.x` 或更高版本，说明安装成功。不要使用 22.0～22.4。

如果显示“无法将 node 识别为命令”，先关闭所有 PowerShell 和资源管理器窗口再重开；仍然无效时重新安装 Node.js，并确认安装程序把 Node 加入了 PATH。

**本节成功标志：** `node --version` 能输出 22.5 或更高的版本号。

## 3. 安装和配置 NapCat

NapCat 是电脑上真正保持 QQ 在线的一端。Nyanya Gateway 不保存真实 QQ 密码，只通过 NapCat 提供的 OneBot 接口收发消息。

NapCat 的安装方式可能随版本变化，请优先按照 [NapCat 官方安装文档](https://napneko.github.io/guide/install) 完成安装和 QQ 登录。本教程只负责说明与 Nyanya Gateway 有关的网络配置。

### 3.1 登录 NapCat WebUI

启动 NapCat 后，控制台通常会显示 WebUI 地址和一段随机 token，地址常见形式为：

```text
http://127.0.0.1:6099/webui?token=一段随机内容
```

用电脑浏览器打开控制台显示的实际地址。端口被占用时，NapCat 可能会自动改用 6100、6101 等端口，所以请以控制台输出为准，不要死记 6099。

在 WebUI 中完成 QQ 登录，并确认账号显示在线。初次登录时 NapCat 可能要求修改 WebUI 密码，按页面提示完成即可。

### 3.2 新建“WebSocket 服务端”

进入 NapCat WebUI 的“网络配置”，点击“新建”，选择：

```text
WebSocket 服务端
```

有些版本会在旁边标注“正向 WS”或“正向 WebSocket”。这里一定要选**服务端**，不要选“WebSocket 客户端/反向 WS”。原因很简单：Nyanya Gateway 会主动连接 NapCat，所以 NapCat 必须在本机开一个端口等待网关连接。

建议填写：

| 选项 | 建议值 | 解释 |
| --- | --- | --- |
| 名称 | `nyanya-gateway` | 只是方便你识别 |
| 主机 / Host | `127.0.0.1` | NapCat 和网关在同一台电脑上，不需要对局域网开放 |
| 端口 / Port | `3001` | 项目默认值 |
| 消息格式 | `array` | 保持 OneBot 数组格式 |
| Token | 自己设置一段英文和数字 | 稍后原样填入 `config.json` |
| 启用 | 开启 | 保存时启用，或保存后手动打开 |

token 可以先用 12～24 位英文和数字，例如自行生成的随机字符串。不要使用 QQ 密码，也不要把教程中的示例文字原样当作 token。

保存后，NapCat 日志应显示 WebSocket 服务已在 3001 端口启动。NapCat 官方对“正向/反向”的说明可参考 [WebUI 网络配置指南](https://napneko.github.io/config/basic)。

**本节成功标志：** NapCat 中的 QQ 在线，网络配置里有一个已启用的 WebSocket 服务端，地址为 `127.0.0.1:3001`。

## 4. 配置 Gateway Class

打开解压目录，再进入：

```text
nyanya-gateway-class
```

### 4.1 创建自己的配置文件

找到 `config.example.json`，复制一份，再把副本改名为：

```text
config.json
```

Windows 默认可能隐藏扩展名。建议在资源管理器顶部打开“查看 → 显示 → 文件扩展名”，确认最后不是 `config.json.json`。

也可以在发布包顶层打开 PowerShell，执行：

```powershell
Copy-Item .\nyanya-gateway-class\config.example.json .\nyanya-gateway-class\config.json
```

### 4.2 填写三个关键项目

右键 `config.json`，用记事本打开。第一次使用只需要认真检查下面几项：

```json
{
  "host": "0.0.0.0",
  "port": 14000,
  "onebotUrl": "ws://127.0.0.1:3001",
  "onebotToken": "填入你在 NapCat 中设置的 token",
  "deviceUin": 0,
  "deviceToken": "换成你自己的老手机登录密码"
}
```

请在原有完整文件中修改值，不要把整个文件删成上面六行。每一行末尾的英文逗号也不要随意删除。

- `onebotUrl`：如果 NapCat 使用本教程推荐的 3001 端口，保持不变。
- `onebotToken`：必须和 NapCat WebSocket 服务端的 token 一字不差。NapCat 没有设置 token 时可以留空，但不建议长期这样使用。
- `deviceUin`：新手建议保持 `0`。网关连接 NapCat 后会自动采用当前在线 QQ 号。
- `deviceToken`：自己设置的老手机登录密码。建议 8～16 位英文和数字，不用中文、空格或超长字符串，因为一些旧客户端的密码输入框会截断内容。

例如，你可以把 `deviceToken` 改成你自己生成的 `Nya26Ab93K`。这个例子只是展示格式，请不要照抄。

保存后，如果记事本询问编码，选择 UTF-8。

**本节成功标志：** `config.json` 存在，NapCat token 已正确填写，`deviceToken` 已换成只有你知道的值。

## 5. 第一次启动网关

确保 NapCat 已经登录，然后双击：

```text
nyanya-gateway-class\启动网关.bat
```

第一次启动时，Windows 防火墙可能询问是否允许 Node.js 通信。只勾选“专用网络/私人网络”，点击“允许访问”；不建议对公用网络开放。

启动窗口会先显示三个本地服务：

- 老客户端 TCP：`0.0.0.0:14000`；
- 管理页：`http://127.0.0.1:13980/`；
- 媒体/WAP：`0.0.0.0:13981`。

接着等待 NapCat 连接。理想日志包含类似内容：

```text
[napcat] 已连接 ws://127.0.0.1:3001
[napcat] 镜像已刷新：self=你的QQ号(你的昵称) 好友=... 群=...
```

“镜像已刷新”不是建立了另一个 QQ 账号，它只是把 NapCat 返回的好友和群资料缓存成老客户端能读取的格式。

可以在电脑浏览器打开 <http://127.0.0.1:13980/> 查看连接状态、好友数、群数和最近日志。这个页面默认只允许本机访问。

请保持网关窗口和 NapCat 都不要关闭。按 `Ctrl + C` 会停止网关。

**本节成功标志：** 日志出现“已连接”和“镜像已刷新”，其中 `self` 是你在 NapCat 登录的 QQ 号，好友数和群数不是异常的 0。

接下来只选择与你手机相符的一条路线：

- J2ME 手机：继续阅读第 6 节；
- Symbian QQ：跳到第 7 节。

## 6. J2ME 路线：注入并安装自己的 JAR

Gateway Class 发布包已经包含补丁工具及依赖。你需要准备自己合法持有的 MobileQQ  JAR，本项目不提供任何具体的手机QQ安装包。

### 6.1 先确认电脑连接的是正确网络

JAR 注入器会自动检测电脑当前的局域网 IPv4，并把它写进客户端。因此，运行补丁前要先让电脑连接到以后给手机使用的那个家庭网络。

如果补丁完成后换了路由器、电脑 IP 发生变化，旧补丁 JAR 可能无法连接。遇到这种情况，只要在新网络下重新运行一次注入器并重新安装生成的 JAR。

### 6.2 运行注入器

双击：

```text
nyanya-gateway-class\制作客户端.bat
```

窗口会要求输入原始 JAR 的完整路径。你可以：

- 把 JAR 文件直接拖到窗口里，再按 Enter；或
- 在资源管理器中按住 Shift 右键文件，复制文件路径，再粘贴到窗口。

工具会显示自动选择的网卡和电脑 IP，例如：

```text
自动选择网卡: Wi-Fi (192.168.1.25)
客户端将连接到本机局域网地址：192.168.1.25
```

确认这个地址属于电脑当前使用的家庭网络。随后工具会解包并识别 JAR：两种已知 MobileQQ 12.0.16 布局会获得完整的 TCP、HTTP/WAP 和群网页补丁；其他可识别出 TCP 14000 入口的版本会生成明确标注的“实验性 TCP 核心版”，只重定向核心 TCP 并封闭剩余公网入口。

工具随后生成：

```text
nyanya-gateway-class\dist\patched-client.jar
nyanya-gateway-class\dist\patched-client.jad
```

看到“制作完成”才算完成打包，同时要查看输出中的 `PatchProfile`、`SupportLevel` 和 `Warnings`。`SupportLevel: full` 表示该字节码布局支持完整补丁；`experimental-tcp` 只表示地址替换和局域网隔离通过，不能据此认定登录、好友或消息协议兼容。如果提示找不到 JAR，通常是路径错误或文件还在压缩包里；重新解压原始 JAR 后再试。带签名的 JAR 会被拒绝，避免生成签名已经失效的安装包。

推荐选择 **QQ2009 及以上版本**。QQ2008 及以下可能无法完成登录；已测试的 QQ2008 12.05.2 会提示“付费用户余额不足（ID 31）”。在这里它是旧客户端协议不兼容的表现，不代表真实 QQ 账户余额不足。注入器仍可能成功生成 JAR，但成功打包不等于该版本能够登录。

### 6.3 把客户端传到手机

通过数据线、存储卡或蓝牙，把 `patched-client.jar` 和 `patched-client.jad` 一起传到手机。不同设备的安装方式略有差异：

- 支持直接安装 JAR 的手机：打开 `patched-client.jar` 安装；
- 要求 JAD 的手机：让 JAD 和 JAR 位于同一目录，再打开 `patched-client.jad` 或由套件管理器安装；
- 如果旧版本已经安装且提示冲突，先备份需要的数据，再卸载旧版本后安装补丁版。

第一次联网时，Java 可能询问是否允许网络访问。选择允许，并尽量把权限设置为“总是允许”；接入点选择与电脑同一局域网的 Wi-Fi，不要选已经停用的蜂窝数据接入点。

### 6.4 在手机上登录

打开补丁版 MobileQQ：

- QQ 号：填写 NapCat 当前登录的真实 QQ 号；
- 密码：填写 `config.json` 中的 `deviceToken`；
- 不要填写真实 QQ 密码。

登录后先耐心等待。好友列表通常先出现，群组和群成员资料可能还要再等几秒到几十秒。群很多时不要看到空白就立即退出，这会中断客户端的分页初始化。

**J2ME 路线成功标志：** 能登录，能看到自己的正确昵称、好友和群组；让另一个账号发一条私聊和一条群消息，手机能收到；手机回复后，消息能出现在现代 QQ 中。

## 7. Symbian 路线：让 QQ2013 的旧节点进入电脑

Symbian QQ不使用 JAR 注入器。它的服务器地址写在客户端内部，Gateway Class 通过“手机把当前 Wi-Fi 网关指向电脑”的方式接管这些旧节点。

这一步只适用于 Windows，并且需要管理员权限。

### 7.1 启动路由脚本

先确认 Gateway Class 正在运行，再双击：

```text
nyanya-gateway-class\启用Symbian路由.bat
```

Windows 会弹出用户账户控制（UAC），点击“是”。管理员窗口会自动检测电脑的局域网 IP，并停在类似下面的提示：

```text
电脑局域网 IP：192.168.1.25
1. 手机 IP 改为手动并填写同网段固定地址
2. 子网掩码填写与电脑相同的值
3. 把“网关”地址改为电脑 IP：192.168.1.25
```

此时先不要按 Enter，保持窗口打开，拿起手机设置 Wi-Fi。

请注意：Symbian 端不能在“手机 IP 地址仍为自动获取”的情况下只改默认网关。实际设备测试表明，必须先设置固定的手机 IPv4 地址和子网掩码，默认网关才会按填写的电脑 IP 生效。

### 7.2 设置固定 IPv4、子网掩码和 Wi-Fi 网关

不同 Symbian 机型的菜单名称会有少量差异，常见路径是：

```text
设置 → 连接功能/连接 → 承载方式/接入点
→ 互联网 → 当前使用的 Wi-Fi → 选项 → 高级设置 → IPv4 设置
```

#### 第一步：记录手机原来的网络参数

在改成手动配置以前，先让手机正常连接这个 Wi-Fi，并记下或拍照保存：

- 手机当前自动获得的 IPv4 地址；
- 原来的默认网关，通常是路由器地址；
- 原来的 DNS 设置；
- 当前 Wi-Fi 的名称。

许多 Symbian 机型可以在“连接管理/连接管理器 → 当前连接 → 详情”中看到手机当前 IP；也可以在路由器管理页面的“已连接设备/DHCP 客户端”中查找这部手机。

再在电脑上按 `Win + R`，输入 `cmd`，运行：

```text
ipconfig
```

找到正在使用、而且 IPv4 地址与路由脚本显示一致的 Wi-Fi 或以太网适配器，记下它的“子网掩码”。家庭网络最常见的是 `255.255.255.0`，但请以电脑实际显示的数值为准，不要看到本教程的示例就直接照抄。

#### 第二步：给手机填写固定 IPv4

进入当前 Wi-Fi 的“高级设置 → IPv4 设置”，把“手机 IP 地址/IPv4 地址”从“自动”改成“手动”或“用户定义”。然后按下面填写：

| Symbian 设置项 | 应填写什么 |
| --- | --- |
| 手机 IP 地址 | 手机刚才自动获得的地址，或路由器专门为这部手机保留的地址 |
| 子网掩码 | 与电脑当前适配器完全相同的子网掩码 |
| 默认网关/网关地址 | `启用Symbian路由.bat` 显示的**电脑局域网 IP** |
| DNS | 保持原值；如果手动模式强制填写，就填写改动前记录的 DNS |

例如，假设当前网络是：

```text
电脑 IP：       192.168.1.25
电脑子网掩码： 255.255.255.0
手机原 IP：    192.168.1.68
路由器原网关： 192.168.1.1
```

那么手机应填写：

```text
手机 IP 地址： 192.168.1.68
子网掩码：     255.255.255.0
默认网关：     192.168.1.25    ← 这里填电脑 IP
DNS：          保持手机原设置
```

电脑 IP、手机 IP 和路由器 IP 是三个不同的地址。手机 IP 不能填成电脑 IP、路由器 IP 或局域网中其他设备正在使用的地址，否则会发生 IP 冲突。第一次短时间测试，最简单的做法是使用手机刚刚由 DHCP 自动获得的地址；长期使用则建议在路由器中按手机 WLAN MAC 地址保留这个 IP，避免以后被分配给其他设备。

有些 Symbian 机型会先把“默认网关”显示为灰色，只有填写完固定手机 IP 和子网掩码后才能编辑，这是正常现象。

#### 第三步：重新连接并启用电脑路由

保存设置，让手机断开并重新连接一次当前 Wi-Fi。确认手机仍能连上该接入点，再回到电脑的管理员窗口按 Enter。脚本会临时添加旧 QQ 节点地址和局域网防火墙规则，并显示：

```text
Symbian 旧节点路由已接管，手机连接会落到本机 14000
```

保持这个管理员窗口打开。不要提前按第二次 Enter，因为第二次 Enter 会恢复并关闭路由。

### 7.3 登录 QQ

打开手机 QQ，选择刚才修改的 Wi-Fi 接入点：

- QQ 号：填写 NapCat 当前在线的真实 QQ 号；
- 密码：填写 `config.json` 中的 `deviceToken`；
- 不要填写真实 QQ 密码。

好友分页完成后，网关才会继续发送群组和群资料。群较多时请等待几秒到几十秒，不要在初始化过程中立刻退出。

**Symbian 路线成功标志：** QQ能登录，好友和群组逐步出现，私聊与群聊文字消息可以双向收发。

### 7.4 使用结束后恢复网络

退出 QQ后：

1. 回到电脑的 Symbian 路由管理员窗口，按 Enter；
2. 看到“已恢复网络设置，路由接管结束”；
3. 回到手机当前 Wi-Fi 的 IPv4 设置，把“手机 IP 地址”恢复为自动获取，或者完整恢复改动前记录的固定 IP、子网掩码和默认网关；
4. 如果之前改动了 DNS，也把 DNS 恢复为自动获取或原值；
5. 断开并重新连接一次 Wi-Fi。

电脑端脚本只负责恢复电脑上的临时配置，不会自动修改手机。忘记恢复手机的 IPv4 和网关设置，可能导致手机之后无法正常访问互联网。

## 8. 完成后的正确使用顺序

以后使用，不需要重复安装或重新注入。按这个顺序启动即可：

1. 让电脑接入原来的局域网；
2. 启动 NapCat，确认 QQ 在线；
3. 双击 Gateway Class 的 `启动网关.bat`；
4. 等待日志出现“已连接”和“镜像已刷新”；
5. Symbian 用户再运行 `启用Symbian路由.bat` 并确认手机 Wi-Fi 网关；J2ME 用户跳过这一步；
6. 打开老手机 QQ 登录。

关闭时反过来：先退出手机 QQ，再恢复 Symbian 路由，然后在网关窗口按 `Ctrl + C`，最后按需要关闭 NapCat。

如果电脑的局域网 IP 没变，J2ME 补丁 JAR 不需要重做。Symbian 路由脚本每次都会重新检测电脑 IP。

## 9. 验收：不要只看“登录成功”

建议按下面顺序完整测试一次：

1. **身份：** 手机显示的是 NapCat 当前账号的真实 QQ 昵称，而不是某个群名片。
2. **好友：** 好友列表能展开，名称和备注基本正常。
3. **群组：** 等待初始化完成后，真实群组能逐步出现，而不是只有一个占位群。
4. **群成员名称：** 新群消息尽量显示群名片；没有群名片时退回 QQ 昵称，资料尚未取得时才可能暂时显示 QQ 号。
5. **接收私聊：** 用另一个账号给当前 QQ 发一条纯文字消息。
6. **发送私聊：** 从老手机回复一条纯文字消息。
7. **接收群聊：** 让另一个群成员在一个已加载的群发纯文字。
8. **发送群聊：** 从老手机在同一群回复，现代 QQ 应能看到。
9. **群消息开关：** J2ME 用户可把某个群设为不接收，再让群成员测试；如果需要绝对屏蔽，可使用网关配置中的 `mutedGroupIds`。

图片方面：群聊里的图片会以可点击的「[图片]」气泡出现，点开可看图；私聊图片则以一条 WAP 链接给出。语音、文件和复杂卡片目前不属于完整转发范围，第一次验收请先用纯文字。

## 10. 常见故障：按“卡在哪一步”排查

### 10.1 双击启动网关后立刻关闭

先在 `nyanya-gateway-class` 文件夹空白处按住 Shift 右键，选择“在此处打开 PowerShell”，执行：

```powershell
node server.js
```

这样错误不会一闪而过。常见原因：

- `node is not recognized`：Node.js 未安装或 PATH 尚未刷新；
- `bad config.json`：配置文件的引号、逗号或 JSON 格式被改坏；
- `EADDRINUSE`：14000、13980 或 13981 端口已被另一个程序占用；
- 目录仍在 ZIP 内：先完整解压。

配置文件改坏时，先把现有文件改名留作备份，再重新复制 `config.example.json`，只修改 token。

### 10.2 网关启动了，但一直没有“NapCat 已连接”

依次检查：

1. NapCat 中的 QQ 是否真的在线；
2. 创建的是“WebSocket **服务端/正向 WS**”，不是客户端/反向 WS；
3. NapCat 端口是不是 3001；
4. `onebotUrl` 是否为 `ws://127.0.0.1:3001`；
5. `onebotToken` 是否和 NapCat 完全一致，包括大小写；
6. 修改配置后是否重启了网关。

如果 NapCat 使用了别的端口，例如 3002，就把 `onebotUrl` 同步改成 `ws://127.0.0.1:3002`。

### 10.3 已连接 NapCat，但好友数或群数为 0

先打开 <http://127.0.0.1:13980/> 查看状态和日志。确认 NapCat 当前登录的账号本身确实有好友/群，并等待一次“镜像已刷新”。

若日志显示 `get_friend_list`、`get_group_list` 或群成员接口失败，问题在 NapCat/QQ 上联，不在手机。先重启 NapCat 并确认其版本与当前 QQ 兼容，再重启网关。

### 10.4 J2ME 手机连接超时

- 手机和电脑是否仍在同一局域网；
- 注入器显示的电脑 IP 是否还是电脑现在的 IP；
- Windows 防火墙是否允许 Node.js 的“专用网络”通信；
- 网关窗口是否仍显示 14000 正在监听；
- 手机是否选择了 Wi-Fi 接入点，而不是旧蜂窝接入点；
- 补丁 JAR 是否是在电脑切换到当前网络之后生成的。

电脑 IP 变化是最常见原因。重新运行 `制作客户端.bat`、重新传输并安装生成的 JAR 即可。

### 10.5 Symbian QQ 仍然连不上

- 是否先启动了 Gateway Class；
- `启用Symbian路由.bat` 是否通过 UAC 取得管理员权限；
- 管理员窗口是否仍保持“已接管”状态；
- 手机 IP 地址是否已经从“自动”改为“手动/固定”；
- 固定手机 IP 是否与电脑处于同一子网，并且没有和电脑、路由器或其他设备重复；
- 手机子网掩码是否与电脑当前适配器一致；
- 手机当前 Wi-Fi 的“网关”是否真的是脚本显示的电脑 IP；
- 是否误把手机 IP 或 `127.0.0.1` 填进了网关栏；
- 是否在公共/访客 Wi-Fi 中被设备隔离。

路由脚本不要求你在电脑上输入手机 IP，也不会把防火墙规则绑定到某个手机地址；但 Symbian 自己的 Wi-Fi 设置必须有一个有效的固定 IP 和子网掩码。先确认“手机固定 IP 与电脑同网段、子网掩码相同、手机默认网关指向电脑”这三项都正确。

### 10.6 手机提示密码错误

- QQ 号必须是 NapCat 当前在线账号的 QQ 号；
- 密码栏必须是 `deviceToken`，不是真实 QQ 密码，也不是 NapCat token；
- `deviceToken` 大小写必须一致；
- 旧客户端可能截断过长密码，建议使用 8～16 位英文和数字；
- 修改 `deviceToken` 后必须重启网关，等镜像刷新后再登录。

### 10.7 能登录，但好友或群组暂时空白

不要马上退出。旧客户端需要按它当年的方式分页请求资料：一般先加载好友详情和好友名册，然后才建立群列表和群资料。群和好友较多时，可能需要几秒到几十秒。

同时查看网关日志是否已经显示正常的好友数和群数。如果现代 QQ 确实有群、网关也显示群数正常，而手机长时间仍为空，再保留 `nyanya-gateway-class\nyanya-data\gateway.jsonl` 日志用于排查。

### 10.8 能收到消息，但发送失败

- 确认 NapCat 账号仍在线；
- 群聊发送时确认账号还在群内且未被禁言；
- 不要连续快速发送，默认存在每分钟发送上限；
- 查看日志中的“私聊发送失败”或“群发送失败”原因；
- 先用纯文字测试，图片和语音不是第一阶段的完整转发范围。

### 10.9 不想接收某些群消息

J2ME MobileQQ 的群消息接收设置会由网关记录并执行。除此之外，还可以在 `config.json` 中进行网关侧强制控制：

```json
"pushGroupMessages": true,
"mutedGroupIds": [123456789, 987654321]
```

- `pushGroupMessages` 改成 `false`：不向老手机推送任何群消息；
- `mutedGroupIds`：填真实 QQ 群号，只屏蔽列出的群；
- 修改后重启网关。

屏蔽只影响网关是否向老手机推送，NapCat 和现代 QQ 仍然会收到这些消息。为了排障，消息内容也可能出现在电脑本地日志中。

## 11. 数据、升级和备份

Gateway Class 的个人运行数据主要在：

```text
nyanya-gateway-class\config.json
nyanya-gateway-class\nyanya-data\
```

升级前：

1. 退出手机 QQ；
2. 恢复 Symbian 路由；
3. 在网关窗口按 `Ctrl + C`；
4. 复制备份 `config.json` 和整个 `nyanya-data` 文件夹；
5. 把新版解压到新目录；
6. 再复制自己的配置和数据。

不要在网关运行时只复制 `nyanya.sqlite`。SQLite 可能还在使用 WAL 文件，单独复制主文件可能得到不完整备份。最稳妥的方法是停止网关后复制整个数据目录。

J2ME 用户升级网关后通常不用重新注入 JAR；只有电脑 IP、网关端口或补丁逻辑变化时才需要重做。

## 12. 使用边界和安全提醒

- 一个 Gateway Class 实例对应一个 NapCat QQ 账号。
- 当前重点是好友、群组、昵称/群名片和双向文字消息，外加群聊图片的收发。
- 群消息不做离线补发；手机离线期间的群消息请在现代 QQ 查看。
- 图片：群聊图片以原生气泡呈现并可点开查看，私聊图片以 WAP 链接给出；手机在群聊里发的图片会转发到真实 QQ。语音和复杂富媒体仍只会降级为本地文件或文字提示。
- 搜索用户、加好友、好友验证、建群、邀请和踢人等操作没有完整 OneBot 映射。
- 网关使用局域网明文协议，不要把 14000、13980、13981 或 NapCat 端口映射到公网。需要异地访问时请改用 `nyanya-gateway-class/异地部署.md` 里的形态并自行补防护。
- NapCat 和第三方 QQ 协议工具可能触发强制下线、限制登录、账号冻结等风控。不要使用主力账号；因风控或封禁造成的账号及数据损失由使用者自行承担，本项目及贡献者不承担责任。
- 请只使用自己合法持有的 JAR/SIS，不要把原版客户端重新打包进项目发布物。

如果你已经完成本教程，后续需要改端口、调整群同步或查看全部配置字段，请继续阅读 [Nyanya Gateway 使用与配置手册](使用与配置手册.md)。
