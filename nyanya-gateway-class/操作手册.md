## 0. 架构总览（frp 方案）

```
老手机 / 模拟器（JAR 指向服务器）
        │ 公网 TCP 14000 / 13981
        ▼
┌────────────────────────── 云服务器 <服务器公网IP> ─────────────────────────┐
│  网关 nyanya-gateway（systemd）   ← 老手机接入、事件翻译、历史回放            │
│      │ 连本机 127.0.0.1:3001                                                │
│  frps（systemd，bindPort <frps端口>）  ← 3001 由 frps 监听，iptables 只放回环 │
└────────────────────────────────────────────────────────────────────────────┘
        ▲  出站长连接（家里主动连服务器，不依赖家里公网/固定 IP）
        │  frpc 连 <服务器公网IP>:<frps端口>，反向代理本机 3001
┌────────────────────────── 家里电脑（Windows）──────────────────────────────┐
│  NapCatQQ Desktop（D:\napcatqq\）  ← QQ <你的QQ号>（胖虎），ws 127.0.0.1:3001 │
│  frpc（D:\AIProject\QQ2011\frp\）                  ← 连服务器，把 127.0.0.1:3001 映射到服务器 3001│
└────────────────────────────────────────────────────────────────────────────┘
```

### 端口一览表

| 端口 | 位置 | 协议 | 用途 | 暴露面 |
|---|---|---|---|---|
| 14000 | 服务器 | TCP | 老手机登录与消息 | 公网（必须） |
| 13981 | 服务器 | TCP | 媒体 / WAP（看图、看群记录） | 公网（必须） |
| 13980 | 服务器 | TCP | 管理页（**无鉴权**） | 只绑 `127.0.0.1`，不对外 |
| <frps端口> | 服务器 | TCP | frps 与 frpc 通信 | 公网（frp 专用） |
| 3001 | 服务器 | TCP | NapCat WS（frp 映射目标） | **iptables 锁死只放 127.0.0.1** |
| 3001 | 家里 | TCP | NapCat OneBot 正向 WS | 只绑 `127.0.0.1` |
| <SSH端口> | 服务器 | TCP | SSH 管理 | 公网（运维用） |

### 三端角色

| 端 | 职责 | 是否随换电脑变化 |
|---|---|---|
| 老手机 / 模拟器 | 装注入后的 JAR，连服务器 14000/13981 | 不随换电脑变（指向服务器） |
| 云服务器 | 网关 + frps + 防火墙 | **完全不动** |
| 家里电脑 | NapCat + frpc | **可迁移、可重启** |

## 1. 服务器侧（<服务器公网IP>）

### 1.1 环境与目录布局

| 项 | 实际值 |
|---|---|
| 系统 | Ubuntu 24.04 LTS / x86_64 |
| SSH | 端口 `<SSH端口>`，本地 ssh 别名 `servername`（root + `id_ed25519`） |
| 数据盘 | `/data`（`/dev/vdb1`，89G）——**一律放这里，禁用系统盘 `/`** |
| Node | v24.18.0 官方二进制，解到 `/data/jar/node24`，软链 `/usr/local/bin/{node,npm,npx}` |
| 网关代码 | `/data/jar/nyanya/gateway/nyanya-gateway-class/`（`packages/` 同级） |
| 数据 | `/data/jar/nyanya/data/`（`nyanya.sqlite`、`gateway.jsonl`） |
| frp | `/data/jar/frp/`（`frps`、`frpc`、`frps.toml`、`.frp-token`） |

> **目录是硬约束**：代码里跨包引用全是相对路径（`server.js` → `../packages/gateway-core`，
> `core/napcat-backend.js` → `../../packages/onebot-adapter`、`../../packages/gateway-core`）。
> 所以 `packages/` **必须是 `nyanya-gateway-class/` 的兄弟目录**。项目无第三方 npm 依赖，
> **不需要 `npm install`**，传上去就能 `node server.js`。

### 1.2 config.json 配置

位置：`/data/jar/nyanya/gateway/nyanya-gateway-class/config.json`。

关键字段（当前实际值）：

```json
{
  "onebotUrl": "ws://127.0.0.1:3001",
  "onebotToken": "<与 NapCat OneBot 的 token 一致>",
  "deviceToken": "<老客户端登录密码，实际值只记在服务器，勿写进文档>",
  "dataDir": "/data/jar/nyanya/data",
  "mediaPublicHost": "<服务器公网IP>",
  "loginPublicHost": "<服务器公网IP>",
  "adminHost": "127.0.0.1",
  "adminPort": 13980,
  "mobileHost": "0.0.0.0",
  "mobilePort": 13981,
  "replayCursorTtlMs": 120000
}
```

要点：

- **`mediaPublicHost` 必须写死公网地址**。留空会自动探测本机第一个非回环 IPv4，服务器上可能探到
  `172.17.x.x`（docker0）或云内网地址，推给手机的收图链接就成了死地址。
- **`loginPublicHost` 只能写 IPv4 字面量**（`legacy/protocol.js` 的 `ipv4ToBuffer()` 校验，拒域名/IPv6/
  前导零/`0.0.0.0`）。只影响登录响应报文，**不改变手机实际连的地址**（那由 JAR 常量池定）。
- **`adminHost` 保持 `127.0.0.1`**：管理页无鉴权，只绑本机，用 SSH 转发访问。
- **`deviceToken` = 老客户端登录密码**（不是 QQ 密码）。手机登录时密码栏填这个值。
- **`replayCursorTtlMs` = 120000（2 分钟）**：**只作用于群回放水位**（群窗口是内存、重启要全量补历史），
  调太大会导致「重启被误判为重连、群窗口空」的 bug（详见 4.3）。
- **私聊回放水位是「永不过期」的**（代码里写死 `ttlMs=0`，不读此配置）：私聊写本机 RMS、不怕重启，
  重连只需增量。若和群共用短 TTL，客户端周期性重连时会把「加好友那句系统文案」反复重推
  （「好友通过通知周期性弹」的根因）。

**改 config.json 后的标准动作**（必须三步，缺一不可）：

```bash
vi /data/jar/nyanya/gateway/nyanya-gateway-class/config.json
chown nyanya:nyanya /data/jar/nyanya/gateway/nyanya-gateway-class/config.json
chmod 600 /data/jar/nyanya/gateway/nyanya-gateway-class/config.json
systemctl restart nyanya-gateway
```

> 漏了 `chown nyanya:nyanya` + `chmod 600` 会导致服务读不到配置。重启后日志应出现
> `设备账号密码已同步为 config 中的 token`。

### 1.3 网关服务管理（systemd）

服务名：`nyanya-gateway`（unit：`/etc/systemd/system/nyanya-gateway.service`，`User=nyanya`、
`Restart=always`、`RequiresMountsFor=/data/jar/nyanya`）。

常用命令：

```bash
systemctl status nyanya-gateway        # 看状态
systemctl restart nyanya-gateway       # 重启（改 config 后）
systemctl stop nyanya-gateway          # 停止
journalctl -u nyanya-gateway -f        # 实时看服务日志
tail -f /data/jar/nyanya/data/gateway.jsonl   # 实时看事件日志（含消息、回放、NapCat 状态）
```

### 1.4 frps（systemd）

frp 版本：**v0.71.0**。二进制在 `/data/jar/frp/`。

- 配置：`/data/jar/frp/frps.toml`
- 认证 token：`/data/jar/frp/.frp-token`（mode 600，与家里 `frpc.toml` 一致）
- 服务：`frps.service`（`ExecStart=/data/jar/frp/frps -c /data/jar/frp/frps.toml`）

`frps.toml` 内容：

```toml
bindPort = <frps端口>
auth.token = "<与家里 frpc.toml 一致，实际值在 /data/jar/frp/.frp-token>"
```

常用命令：

```bash
systemctl status frps
systemctl restart frps
journalctl -u frps -f                  # 看 proxy 注册 / login 日志
```

### 1.5 防火墙（3001 锁死，安全红线）

frps 的 tcp proxy `remotePort` 会监听在 `0.0.0.0`，即 NapCat WS 会暴露公网。必须用 iptables 锁死。

已落地为 systemd 服务 `frp-firewall`（`Type=oneshot` + `RemainAfterExit=yes`，开机自动加载）：

```bash
iptables -A INPUT -p tcp --dport 3001 ! -s 127.0.0.1 -j DROP
```

常用命令：

```bash
systemctl status frp-firewall
iptables -L INPUT -n --line-numbers | grep ':3001'   # 确认 DROP 规则在
ss -ltnp | grep ':3001'                              # 3001 应只被 frps 监听
```

### 1.6 安全组

- **放行**：`14000`、`13981`（老手机接入）、`<frps端口>`（frp）、`<SSH端口>`（SSH）。
- **禁止对外**：`13980`（管理页）、`3001`（NapCat WS，靠 iptables 锁）。

管理页访问方式（不开放端口）：

```bash
ssh -L 13980:127.0.0.1:13980 servername
# 本地浏览器打开 http://127.0.0.1:13980/
```

> **强烈建议**：给 14000 / 13981 配 IP 白名单（只放行你手机所在网络的出口 IP）。老 QQ 协议是明文、
> 无加密、无鉴权，IP 白名单是唯一的门锁。

## 2. 本机侧（家里 Windows）

### 2.1 NapCat

- 位置：`D:\napcatqq\`，程序 `D:\napcatqq\NapCatQQ-Desktop.exe`。
- 登录 QQ：**<你的QQ号>（胖虎）**。注意：**手机上的 QQ 号必须等于 NapCat 当前登录的 `self_id`**。
- OneBot：WebSocket 服务端（正向 WS）监听 `127.0.0.1:3001`，token 与服务器 `config.json` 的
  `onebotToken` 一致。配置在 `D:\napcatqq\data\components\NapCatQQ\config\`。

**启动**：双击 `NapCatQQ-Desktop.exe`，确认胖虎在线即可。NapCat 目前**不自动启动**（`autoStart=false`），
电脑重启后需手动开（见 3.1）。

### 2.2 frpc

- 位置：`D:\AIProject\QQ2011\frp\frp_0.71.0_windows_amd64\`，程序 `frpc.exe`，配置 `frpc.toml`。
- 启动脚本：`D:\AIProject\QQ2011\frp\启动内网穿透客户端.vbs`（已复制到启动文件夹，开机自启）。

`frpc.toml` 内容：

```toml
serverAddr = "<服务器公网IP>"
serverPort = <frps端口>
auth.token = "<与服务器 frps.toml 一致>"

[[proxies]]
name = "napcat"
type = "tcp"
localIP = "127.0.0.1"
localPort = 3001
remotePort = 3001
```

> **注意**：`frpc.toml` 里**不要写 `log.to`**（正斜杠路径会让 frpc 启动即退、日志 0 字节）。
> 日志由 `.vbs` 的 `cmd /c` 重定向到 `D:\AIProject\QQ2011\frp\frpc.log`。

**启动**：双击 `D:\AIProject\QQ2011\frp\启动内网穿透客户端.vbs`（**无窗口、无提示 = 正常**，静默后台跑）。

**验证**：

```powershell
# 看 frpc 日志
D:\AIProject\QQ2011\frp\frpc.log
# 期望出现：login to server success / proxy added [napcat] / start proxy success
```

### 2.3 JAR 注入

双击 `制作客户端.bat` → 选 `2`（公网模式）→ 输入 `<服务器公网IP>` → 输出名默认 `QQ2011.jar`。
（命令行直调 `patch-client.ps1` 作为脚本化用法保留）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\patch-client.ps1 `
  -ClientJar "C:\Users\korea\Desktop\qq\QQ2011_Beta1_Build0012_Unigned.jar" `
  -ServerAddress <服务器公网IP> `
  -Port 14000 `
  -MobilePort 13981 `
  -OutputName QQ2011.jar
```

要点：

- `-ServerAddress` 校验 `^[A-Za-z0-9.-]+$`，公网 IPv4 和域名都支持；同一地址会写进 socket 地址、
  WAP base、guard 白名单三处。
- 常量池替换是变长替换，地址长度变化无妨。
- 产物 `dist/QQ2011.jar`（+ `QQ2011.jad`），装进手机/模拟器。
- 带签名的 JAR 会被拒绝；注入后脚本会断言 `externalNetworkLiteralCount === 0`。

> 本机跑 PowerShell 脚本前先 `Set-ExecutionPolicy -Scope Process Bypass -Force`。

## 3. 日常操作

### 3.1 电脑重启后

| 组件 | 重启后状态 | 你要做的 |
|---|---|---|
| frpc | ✅ 自动启动（`启动内网穿透客户端.vbs` 在启动文件夹） | 不用管 |
| NapCat | ⚠️ 不自动启动 | **手动打开 `NapCatQQ-Desktop.exe`，确认胖虎在线** |

**IP 变了完全不用改任何配置**——frpc 是主动出站连服务器，NapCat 监听回环 `127.0.0.1`，配置里
没有任何地方写死家里电脑的局域网 IP。

### 3.2 换电脑迁移（家里侧）

服务器侧**零改动**。家里侧搬这几样：

| # | 搬什么 | 位置 |
|---|---|---|
| 1 | NapCat 整个目录 | `D:\napcatqq\` |
| 2 | frp 整个目录 | `D:\AIProject\QQ2011\frp\`（`frp.zip` 可不要） |
| 3 | qzone-bridge 整个目录 | `D:\AIProject\QQ2011\qzone-bridge\`（含 `.env`） |
| 4 | 两个自启脚本 | 启动文件夹的 `启动内网穿透客户端.vbs`、`启动QQ空间桥接服务.vbs` |

步骤：

1. 拷 `D:\napcatqq\` → 新电脑 `D:\napcatqq\`（保持路径一致）。
2. 拷 `D:\AIProject\QQ2011\frp\` → 新电脑同路径。
3. 拷 `D:\AIProject\QQ2011\qzone-bridge\` → 新电脑同路径（含 `.env`）。
4. 启动 `NapCatQQ-Desktop.exe`，**重新登录 QQ <你的QQ号>**（登录态绑设备指纹，大概率要重新扫码/短信）。
5. 确认 OneBot WS 仍监听 `127.0.0.1:3001`（拷过去配置会保留，通常不用重配）。
6. 把 `启动内网穿透客户端.vbs`、`启动QQ空间桥接服务.vbs` 复制进启动文件夹 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`。
7. 双击这两个 `.vbs` 启动 frpc 与 qzone-bridge。
8. 老手机登录验证收发。

> **JAR 不用重新注入**：JAR 里写死的是服务器地址，跟家里电脑解耦。只有「换服务器地址」或
> 「换新的老手机/模拟器」才需要重新注入。

### 3.3 修改登录密码（deviceToken）

改 `deviceToken` = 改老客户端登录密码。步骤见 1.2（改 config.json → chown/chmod → restart）。
重启后网关会把库里的设备账号口令同步成新 token（日志 `设备账号密码已同步为 config 中的 token`）。
改完手机上登录密码栏也要同步改。

### 3.4 重新打包发布

本地 monorepo 根目录：

```powershell
npm run release
```

产物 `release/Nyanya-Gateway-Class-v0.1.0/` 和同名 `.zip`。脚本会自动排除 config.json、数据、日志、

## 4. 故障排查

### 4.1 手机能登录，但新消息全空

**先查 frp/隧道，再查协议**。症状极易误判：手机能登录、能同步、历史能回放（这些走本地库），
只有依赖 NapCat 的功能全废（好友/群空、消息不通）。

排查顺序：

```bash
# 1. 家里 NapCat 打开了吗？QQ 在线吗？
# 2. 家里 frpc 起来了吗？
D:\AIProject\QQ2011\frp\frpc.log        # 末尾有没有 start proxy success
# 3. 服务器 3001 是否由 frps 监听？
ssh servername "ss -ltnp | grep :3001"
# 4. 网关 NapCat 是否已连接？
ssh servername "grep -E 'napcat' /data/jar/nyanya/data/gateway.jsonl | tail -5"
```

网关日志若连续刷 `[napcat] NapCat 连接断开，等待重连`，就是家里那条链路断了（家里关机/断网/frpc 没起）。

### 4.2 登录失败，客户端显示「付费用户余额不足 错误ID=31」

**这是 2011 版客户端的误导文案，真实含义是登录被拒（密码错）**，跟余额无关。

- 看网关日志：`login_rejected reason="bad_credentials"` = 密码不对。
- 手机密码栏要填服务器 `config.json` 的 `deviceToken`，**不是 QQ 密码**。
- 鉴权是 `MD5(latin1(密码))` 摘要比对（`store.authenticate(uin, passwordDigest)`），非明文但摘要可重放。

### 4.3 历史回放 / 聊天框空（但聊天记录在）

根因是回放水位（`replayCursorTtlMs`）TTL 太长，把「重启登录」误判成「短时间重连」，只推增量、
增量又是空的。已把 TTL 定为 **120000（2 分钟）**。

- 数据没丢：消息在数据库 `group_messages` / `messages` 里，可手动翻 WAP 群记录（`bid=xxx`）。
- 私聊回放只回放「对方发的」，不回放「自己发的」（老协议 `0x0056` 载荷只有发送者 uin、无接收者 uin，
  自己发的消息客户端无法路由回正确会话）。

**反方向症状：好友通过（加好友系统文案）通知隔一段时间重复弹** —— 私聊水位过期导致的重复重推，
已通过「群/私聊分开水位」根治（私聊水位永不过期）。判断：`private_history_replayed` 日志里
`fresh` 恒等于好友数（全量）而非 `resumed`，且每次 `messages` 都包含那句「我们已成功添加为好友…」。
不要为了修这个去把 `replayCursorTtlMs` 调大——那会让 4.3 的「群窗口空」复发；私聊水位已在代码里
写死永不过期，与 `replayCursorTtlMs` 无关。

### 4.4 手机收图打不开

看网关启动日志里的 **「收图链接基址」** 一行：必须是 `http://<服务器公网IP>:13981`。
出现 `172.x` / `10.x` 说明 `mediaPublicHost` 没写死公网地址。

### 4.5 已知边界（改代码前先确认，别硬扛）

- **NapCat/QQNT 不回推「自己账号在别的端发的消息」**（self 消息）：新版 QQ 同号发的消息，
  模拟器收不到，网关无解（NapCat 日志里 self 消息一律「发送→」，从不「接收←」）。
  出路是双号互聊，或接受此限制。

## 5. 验证顺序

按顺序验，哪一步失败就停在那一步排查：

1. 服务器端口在听：`ssh servername "ss -ltnp | grep -E '14000|13981|<frps端口>'"`。
2. 服务器 3001 由 frps 监听：`ssh servername "ss -ltnp | grep :3001"`。
3. 家里 frpc 连上：`D:\AIProject\QQ2011\frp\frpc.log` 有 `start proxy success`。
4. 网关 NapCat 已连接：`ssh servername "grep -E 'napcat' /data/jar/nyanya/data/gateway.jsonl | tail -3"`。
5. 看网关日志「收图链接基址」= 公网 `13981`、「登录响应 IP」= 公网 IP。
6. 手机登录 → 好友列表 → 群列表。
7. 手机发群消息 → 真 QQ 收到（`group_message_sent`）。
8. 真 QQ 往群里发图 → 手机能看到「查看群图片」→ 点开能看到。
