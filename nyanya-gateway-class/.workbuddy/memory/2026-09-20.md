### 1. `legacy/sqlite-persistence.js` — 核心：save 前做引用收敛
- 新增 `reconcile(data)`：**就地**（同时修正内存模型，避免每轮重复踩坑）剔除会撞外键/唯一约束的行：

    group_members 的 uin 必须在账号里；**group_messages 的 groupId 必须在群里、from 必须在账号里**（本次故障直接原因）；

- 顺序调整：**取数 + 校验全部通过之后才动 store**，消除「内存已改、磁盘没改」的半成品状态。

- 私聊：消息体里出现 `0x15`(偏移n) 且 `n+2` 处是字符 `'3'`(51) → `ew.d = 1`（`im.java:1485`）

| 偏移 | 内容 |
|---|---|
| +0 | `0x0015` 块标记 |
| +2 | `'6'`=图片定义 / `'7'`=引用前面第 N 张 |
| +7、+9 | 两位十进制数字 → 块长（`(十位*10+个位)<<1` = 字节数） |
| +10 | u16，`值-65` = uuid 的**字符数** |
| +18 | **16 字节 = fileid 的 hex ASCII**（`Long.parseLong(s,16)` → 十进制字符串） |
| +98 | uuid 字符串（UTF-16BE） |
解析产物：`ly.g=1`、`ly.h`=uuid 列表(Vector)、`ly.f`=fileid 十进制；文本里该块被替换成字面量 `[图片]`。

拼 URL `http://<IP>/forward.jsp?bid=331&B_UID=<uin>&pic=<uuid>&gid=<群>&time=<秒>&fileid=<十进制>&encodetype=1`，
绑到一个文本为 `[图片]` 的显示项 → **用户点击用内置浏览器打开**（即网关的 WAP 看图页）。

**消息模型（`bl`）**：`b()`=类型（0 文本 / 3 图片）、`a()`=正文、`l()`=图片 uuid 列表、`d()`=fileid。
事件→模型的映射在 `p.java:147-177`（私聊）与 `p.java:193-217`（群）。
